# Voice and tone

Every piece of copy generated by app-store-toolkit—from App Store descriptions to release notes to in-app purchase names—reflects a consistent voice. This voice is a configuration you set once during `/app-store-toolkit:setup` and applies to every skill that creates content, across all locales and releases.

## What voice controls

Voice shapes **how** something is said, not **what** is said. When you generate App Store listing copy with `/app-store-toolkit:aso`, the skill:

1. Gathers context (your app's description, code analysis, user requirements)
2. Reads your configured voice from `.appstore/config.json`
3. Sends a prompt to Claude that includes both: "Here's what the app does" + "Here's the tone you should use"
4. Claude generates keywords, descriptions, promotional text, or release notes following that voice constraint
5. Validates the output against character limits

**All content-generating skills read voice:**
- `/app-store-toolkit:aso` — App Store listing copy (name, subtitle, keywords, description, promotional text)
- `/app-store-toolkit:changelog` — Release notes (what's new for each version)
- `/app-store-toolkit:iap` — In-app purchase display names and descriptions
- `/app-store-toolkit:localize` — Transcreated copy in other languages
- `/app-store-toolkit:audit` — Validation language when detecting drift or issues

## The six presets

Choose one of six preset voices during setup. Each has a personality and works best for certain app categories.

| Preset | Character | Best for | Example |
|--------|-----------|----------|---------|
| **Professional** | Clear, authoritative, measured | Enterprise, productivity, medical apps | "Streamline your team's workflow with precision-built project management." |
| **Casual** | Friendly, conversational, approachable | Social, lifestyle, consumer apps | "Manage your team's projects without the fuss—just the fun part." |
| **Playful** | Energetic, humorous, upbeat | Games, entertainment, design tools | "Your projects called. They want to get stuff done... and have fun." |
| **Technical** | Precise, feature-focused, jargon OK | Developer tools, complex software | "RSA-2048 encryption, WebSocket multiplexing, and async state sync." |
| **Minimal** | Short, direct, no fluff | Utilities, health trackers, note apps | "Organize tasks. Track progress. Ship on time." |
| **Witty** | Clever, observational, slightly dry | Consumer products, independent apps | "We built something so good, we almost kept it to ourselves." |

## The Custom preset

If none of the six fit, choose **Custom** during setup. Custom lets you define:

- **`style_notes`** — free-form guidance for the model (e.g., "Always address the user in second person. Every sentence should feel like advice from a friend. Never use exclamation marks.")
- **`target_audience`** — who the copy speaks to (e.g., "solo iOS developers aged 25–40 who value simplicity", "small business owners managing their first team")

Both fields are sent to Claude along with every generation request, so the model can adapt dynamically.

**Example Custom config:**
```json
{
  "tone": "custom",
  "style_notes": "Use second person. No hype. Focus on outcomes, not features. Each paragraph should pose an implicit question the user is asking.",
  "target_audience": "product managers at mid-size B2B SaaS companies who feel overwhelmed by tool sprawl"
}
```

Custom voices are powerful but require more tuning. If you find yourself tweaking the preset voices heavily, Custom is worth exploring.

## How voice is applied

Here's what happens when you run a content-generating skill:

1. **Load context** — the skill gathers information:
   - Existing metadata from `.appstore/metadata/{locale}/`
   - Your project's CLAUDE.md (if it describes the app)
   - Your README.md (for features and technical details)
   - Source code analysis (if generating changelog or understanding features)
   - User instructions (what you asked for in the command)

2. **Read voice config** — loaded from `.appstore/config.json`:
   ```json
   {
     "tone": "casual",
     "style_notes": null,
     "target_audience": null
   }
   ```

3. **Build the prompt** — the skill constructs a request:
   ```
   Generate an App Store description for an iOS project management app.
   
   Context:
   - App does: help teams plan sprints, assign tasks, track progress
   - Target users: small agile teams (5–20 people)
   - Existing copy: [current description if updating]
   
   Voice: CASUAL
   Definition: Friendly, conversational, uses contractions. Assume the reader wants to feel at ease, not impressed.
   
   Requirements:
   - Max 4000 characters
   - Highlight 3–5 key features
   - Avoid corporate jargon
   
   Generate the description now.
   ```

4. **Validate and regenerate** — the skill checks the output:
   - ✓ Passes character limit → done
   - ✗ Exceeds limit → regenerate with explicit constraint ("Reduce to <4000 chars") up to 2 retries
   - ✗ Still too long after retries → warn user with exact counts and ask to edit manually or choose a different voice

This ensures all generated copy consistently reflects your chosen voice without requiring manual tweaking.

## Translating voice across locales

When you run `/app-store-toolkit:localize`, the plugin transcreates (not translates) your English copy to other languages while preserving voice. **This is crucial because voice doesn't translate literally.**

Example: A Witty tone in English might rely on wordplay that breaks in German. The localizer agent:

1. Reads the English copy and voice config
2. Translates meaning faithfully
3. Adapts humor and tone to work in the target language and culture
4. Preserves the emotional impact, not the exact words

So a Witty English line like "We built something so good, we almost kept it to ourselves" becomes "Dieses Ding ist so verdammt gut, dass wir lange überlegt haben, es nicht zu veröffentlichen" in German—different words, same voice.

See [Locales and localization](locales.md) for the full transcreation workflow.

## Changing voice

To adopt a new voice:

1. **Run setup again:**
   ```
   /app-store-toolkit:setup
   ```
   You'll be prompted to choose a new tone preset (or reconfigure Custom). Claude Code updates `.appstore/config.json` automatically.

2. **Manually edit** (advanced):
   ```json
   // .appstore/config.json
   {
     "tone": "professional",
     "style_notes": null,
     "target_audience": null
   }
   ```

3. **Existing copy is NOT auto-regenerated** — your old listings stay in place. You decide what to refresh:
   - Run `/app-store-toolkit:aso` on specific fields and review the new suggestions
   - Cherry-pick phrases you like from the new generation
   - Keep old copy if it still aligns with your updated voice

Changing voice mid-release is fine—it often signals growth (from Playful → Professional as you scale, or Casual → Technical as you ship for developers).

## Voice drift detection

The `/app-store-toolkit:audit` skill (Phase 5 of the submission readiness check) detects when your live copy has **drifted from your configured voice**. For example:

- Your voice is set to **Minimal** (short, direct)
- But your current description is 1200 words of flowery prose

Drift is flagged as a **QUALITY warning**, not a blocker—you can ignore it if intentional. But it's often a sign that:
- The voice setting doesn't match your app anymore
- You're shipping copy that wasn't generated with the current voice config
- A teammate edited copy without consulting the voice guide

See [Audit deep dive](../workflows/audit-deep-dive.md) for Phase 5 details.

## Best practices

- **Set voice early** — pick a preset that resonates before you start generating copy. It's easier to regenerate a few fields than to rewrite everything mid-campaign.
- **Keep Custom minimal** — if you write 500 words of `style_notes`, you're writing a copy guide. Consider using that energy to build custom system prompts in the model instead.
- **Test before you ship** — generate content, read it aloud, ask a friend. Voice should feel natural, not forced.
- **Revisit voice with your audience** — if your users change (e.g., you expand to enterprise), your voice might too. Re-run audit to surface drift.
- **Localize intentionally** — don't assume your English voice works everywhere. Review transcreated copy carefully, especially humor and brand voice.
